## 1. 项目背景与理论基础

### 1.1 要解决的痛点

传统学习方式大多在**累积知识**（背单词、看懂语法、读教材），却几乎不花时间**训练反应**。结果是：

- 大脑习惯依赖提示（看着字幕跟读、看着答案点头），真实场景中没有提示就卡住；
- 需要先想母语再翻译（或先想理论再推导），无法做到「脱口而出 / 随手就用」；
- 「知道」和「会用」之间存在巨大鸿沟——知识没有转化为可随时调用的技能。

### 1.2 理论基础

本产品的训练机制以 Paul Pimsleur（1967）的记忆理论为起点，并按此后 60 年学习科学的实证共识做了修订：

**（1）间隔重复（Spaced Repetition）与递增间隔回想**

新记忆形成后会立刻开始遗忘。不要等完全忘记才复习，而要在**「快要忘记」的临界点**触发回想。Pimsleur 的参考间隔序列（5 秒 → 25 秒 → 2 分钟 → 10 分钟 → 1 小时 → 5 小时 → 1 天 → 5 天 → 25 天）是磁带媒介限制下的工程近似；现代证据表明最优间隔取决于个体、材料与目标保持期，自适应算法（FSRS，基于 5 亿+ 条真实复习记录的基准测试，同等保持率下复习量少 20–30%）明确优于固定阶梯。**产品策略：固定阶梯作为可替换的冷启动默认，架构上第一天就为自适应算法留好数据与接口（见 F4）。**

**（2）主动回想与测试效应（Active Recall / Testing Effect）**

绝不直接把答案塞给学习者。必须在展示答案前，强迫大脑先进行**主动搜索**（217 项研究元分析确认测试效应稳健）。「想不起来、努力去想」的过程本身就在建立神经连结——即使最终没答出，尝试提取也促进后续学习（预测试效应），前提是随后给纠正性反馈。此外，对句子级材料，**外显产出（说/写出来）显著优于脑中默想**。

**（3）多会话分散成功（Successive Relearning）**

长期保持来自「在多个分散的会话中各达成一次成功提取」，而非单次会话内答对多次——约 3 个分散会话的成功即接近收益上限。会话内的重复是教学动作，不是记忆证据（见 F4.1/F4.11）。

**（4）适度困难（Desirable Difficulty）与交错练习（Interleaving）**

训练难度控制在「稍微努力一下就能想起来」的区间；相邻题目来自不同技能项（交错优于分块，元分析 g≈0.42），初学阶段允许短暂分块过渡。

**（5）刻意练习与纠正性反馈（Deliberate Practice / Corrective Feedback）**

技能自动化需要「尝试 → 即时、具体的反馈 → 修正再试」的循环；口语反馈中「先提示学习者自我修正、后示范正确形式」（prompts 优于直接重铸），且学习者最终必须接触到正确形式。

### 1.3 核心训练流程（影片中的「每天 15 分钟训练法」）

1. **情境化输入**：以真实生活情境（而非翻译提示）作为题面；
2. **强制主动输出**：限时开始作答、尝试输出，之后才展示标准答案，并跟读修正；
3. **多场景泛化**：同一核心技能自动生成不同情境变体，训练举一反三；
4. **严格间隔循环**：会话内短间隔重现刚学内容，跨会话按自适应间隔调度。

## 2. 产品定位

**LearnSkillsAssistant 是一个通用技能训练平台**——它不是知识库，而是「大脑与肌肉反应的健身房」。

- **训练对象**：任何可以表达为「情境 → 快速正确输出」的实用技能。语言口语是最典型的例子，但同样适用于编程惯用法、面试问答、医护流程、销售话术、客服应对等。
- **价值主张**：帮助学生把「知道」的知识，真正转化为「随时能调用」的反射神经。产品价值不在于内容量，而在于**提取速度与自动化程度**。
- **产品独有的「激活时刻」**：间隔回想的会话内循环让用户在**同一次会话内**亲眼看到「1 分钟前还想不起来的句子，现在脱口而出了」——这是即时可感的成长证据，新手引导（F9）的全部使命是把用户在 3 分钟内送到这个时刻。
- **动机设计价值观**：面向学生，健康的动机设计是产品底线——只用真实的进度、真实的调度数据和真实的成长证据做激励，禁止一切操纵性设计（见附录 A 红线）。
- **第一个示例技能包**：中文用户英语口语（高频实用句型），完整对齐影片方法论，作为平台能力的验证载体。
- **成功关键公式**：现代化的记忆调度（Anki/FSRS 传承）+ Pimsleur 式主动回想与情境训练 + AI 即时对话反馈 + 健康的习惯养成设计。

### 2.1 平台策略

| 阶段 | 形态 |
|---|---|
| 先期 | 响应式 Web 应用（PWA），手机/电脑浏览器通用 |
| 后期 | 原生移动 App（iOS/Android），复用核心逻辑层 |

因此**核心领域逻辑必须与 UI 框架解耦**（纯 TypeScript 包），Web 与未来 App 共用同一套调度引擎、会话引擎与数据模型。

## 3. 核心概念模型

```
SkillPack（技能包）
 └── Card（训练卡）×N
      ├── 正面：真实情境描述（如「你想通知同事，明天会议需要改时间」）
      ├── 背面：目标输出（如 "Can we reschedule the meeting tomorrow?"）+ 可选讲解/音频
      ├── MemoryState（卡×用户的当前调度状态：掌握度、下次到期时间——算法内部视图）
      └── ReviewLog（卡×用户的完整复习日志——唯一事实来源，只追加不修改）

Session（训练会话）
 └── 按调度规则从到期卡片 + 新卡组成的一次约 15 分钟的训练（最小达标单元约 3 分钟）

CoachConversation（AI 教练对话）
 └── 围绕某技能包展开的突发情境问答记录
```

- **技能包（SkillPack）**：一组围绕同一技能领域的训练卡集合，含元数据（名称、领域、语言、难度、作者）。内容格式与领域无关，任何「情境→输出」型内容都可以装入。
- **训练卡（Card）**：最小训练单元。正面必须是**情境**，不是答案的直接翻译/提示；背面是目标输出，可附讲解、发音、常见错误。
- **ReviewLog（复习日志）**：每次作答的不可变记录（见 F4.10），调度算法、成功衡量指标与未来算法升级（FSRS 参数拟合）的**唯一事实来源**。
- **MemoryState（记忆状态）**：由 ReviewLog 推导出的当前调度视图；其中「间隔档位」等字段是算法内部实现细节，可整体替换。
- **选材原则**：技能包内容应从「最高频、最实用的少数核心项」开始，拒绝冷僻知识。

## 4. 功能需求

> 未标注优先级的条目默认属于 MVP（P0）；标注【P1】为 Phase 2、【P2】为远期。

### F1 技能包与训练卡管理

- F1.1 内置示例技能包（英语口语高频句型）随产品发布；
- F1.2 用户可浏览、选择、启用/停用技能包；
- F1.3 技能包为开放数据格式（JSON），支持导入/导出，为后期内容生态与创作工具打基础；
- F1.4 【P1】用户/教师可创建和编辑自己的技能包，可由 AI 辅助批量生成卡片草稿；
- F1.5 【P1】语言类技能包支持「听力理解卡」变体：正面为音频（不显示文字），用户先口头复述大意再看文本——保证输入与输出两股训练并存（Nation 四股框架：意义输入/意义输出/语言聚焦/流利度应大致均衡）。

### F2 强制主动输出训练（单卡训练交互）

核心交互流程，任何时候都**不允许先展示答案**：

1. **展示情境**（正面）；
2. **限时开始作答**：启动倒计时（默认 5 秒）。倒计时约束的是**开始作答**的时限，而非说完整句的时限——用户开口/落键后计时暂停，允许完整说完（整句口语产出本身需要数秒，硬时限打断作答会加剧口语焦虑）。系统记录**提取延迟**（题面呈现到开始作答的毫秒数）写入 ReviewLog，作为自动化程度的直接测量。
   - 作答方式：**语音**（Web Speech API 转写，默认推荐）/ **文字**（键盘输入）/ **自评兜底**（在脑中作答后自行标记）。**默认要求外显输出**（出声或打字）——对句子级材料，外显产出显著优于默想；自评模式仅作为不便出声场合的兜底，界面明示「出声或打字作答训练效果更好」；
3. **分级提示**：倒计时到点仍未开始作答时，先给提示（首词/首音），仍答不出才展示完整答案——分级提示比直接给答案保留更多生成效应；
4. **答案与修正复述**：展示标准答案（目标输出 + 可选讲解），同步以 TTS 朗读；修正复述定义为**听后跟读（shadowing）**——先听、再模仿其语音语调复述一遍。卡片数据格式支持音频字段（Phase 1 用 TTS 实时合成，Phase 3 可替换为真人/云语音）；
5. **对照后评分**：打分只能发生在标准答案展示**之后**（强制对照再评，避免学习判断的过度自信），三档行为锚定：「没答出/答错」「答出但明显犹豫或有错漏」「限时内流畅答对」。
   - **语音转写结果仅作为作答记录与参考对照展示，不得单独作为自动判分依据**（浏览器 ASR 对非母语口音词错率显著偏高，假阴性反馈既伤体验又污染调度数据）；用户可一键覆写任何系统建议评分；转写明显失败时提供「重说一次 / 改用键盘」出口。云端发音评分（Phase 3）引入前不做自动发音打分。

> 卡住想不起来不算失败——界面文案与交互要传达「努力回想本身就在建立连结」（预测试效应：即使没答出，尝试提取也促进后续学习）。

### F3 多场景泛化（Scenario Variation）

- F3.1 对同一核心技能项（如句型 "I need more time"），由 AI 自动生成不同情境变体（职场写报告、出门前准备、学校交作业……）；
- F3.2 变体作为衍生卡进入训练流，让学生体会同一技能可迁移到不同场景；
- F3.3 变体生成走 LLM 抽象层（见 F8），生成结果可缓存进技能包避免重复调用；
- F3.4 【P1】**交错编排约束**：同一核心技能的变体卡不得在同一会话内相邻出现，会话编排器保证相邻卡片来自不同核心技能项（交错优于分块）；新技能项首次学习时允许本体 + 首个变体相邻（初学分块豁免），此后一律交错；
- F3.5 【P1】**迁移探针**：每个核心技能项的 AI 变体中随机保留 1 个不进入常规训练流，在该技能项达到「已巩固」（F4.11）后作为一次性迁移测验呈现；其首答成功率单独统计为「泛化率」指标（第 8 章），测验后该变体转为普通卡——没有从未练过的新变体做测试，就无法验证「举一反三」是否真的发生。

### F4 间隔重复调度引擎（Spaced Repetition Engine）

会话内循环与跨会话调度是**两套机制**，证据流必须分开：

- F4.1 **会话内循环（learning steps）**：新学/答错的卡片按短间隔在会话内重现（如约 30 秒 → 2 分钟 → 10 分钟，中间穿插其他卡片，不做无间隔的立即重测）；会话内重现的成绩**仅用于决定该卡是否「毕业」进入跨会话调度，不计入长期记忆强度估计**——几秒后答对只反映工作记忆，计入会系统性高估记忆强度；
- F4.2 **跨会话调度**：冷启动默认使用递增间隔阶梯（1 天 → 5 天 → 25 天，可配置），**首个跨会话间隔不早于次日**（延迟首次跨会话提取比会话内多次成功更能预测长期保持）。固定阶梯定位为**可替换的冷启动默认**；【P1】Phase 2 切换为自适应算法 **FSRS**（候选实现：`ts-fsrs`，MIT 协议，与 F4.5 纯函数要求兼容），固定阶梯保留为无历史数据时的初始参数；
- F4.3 **升降档**：答对升档；答错按当前记忆强度**折减**（如降 2 档或按稳定性乘折减系数），**不重置为初始档**（避免「一次失误清零全部历史」的 ease hell），连续答错才继续下探；
- F4.4 **会话编排**：每次会话 ≈ 15 分钟，「到期复习卡」优先 + 新卡；**新卡遵循每日上限**（默认 5–10 张，可配置）；复习量超出会话容量时按「逾期时间相对间隔的比例」排序截断，其余顺延；
- F4.5 调度算法实现为**纯函数、可单元测试、与 UI 和存储完全解耦**；引擎输入为**完整 ReviewLog 序列**而非仅当前档位——MemoryState 中的档位字段视为算法内部实现细节，可整体替换（这是未来切换 FSRS 的前提）；
- F4.6 到期复习提醒见 F13；
- F4.7 **每日到期上限与积压保护**：单次会话呈现的到期卡数量设上限（默认 ≈ 25 张 / 15 分钟量）。超出部分不显示为「欠账总数」，界面永远只说「今天这一组」，**禁止展示「你有 137 张过期卡」类总积压数字**——积压雪崩（Review Debt）是间隔重复产品被反复验证的头号流失原因，本产品每卡需强制开口，单卡成本更高，必须在引擎层把「回来的那天」设计成轻松的一天；
- F4.8 **回归模式（Welcome-Back Mode）**：检测到用户中断 ≥ 4 天后返回时，自动进入回归会话：暂停新卡，仅取积压中「掌握度最高、最可能答对」的 10–15 张卡（先赢回信心），其余到期卡的到期时间由引擎自动平滑重排到未来 3–7 天。文案基调为欢迎而非追债（「欢迎回来。先从你最拿手的开始」）；
- F4.9 **假期模式**：用户可预先声明 1–14 天暂停，期间调度冻结顺延、不产生积压、不发送任何提醒、streak 以「暂停」态保留；
- F4.10 **复习日志（ReviewLog）**：每次作答生成一条**不可变**记录：卡片 ID、时间戳、计划到期时间、实际延迟、评分档位、提取延迟（ms）、作答方式（语音/文字/自评）、会话 ID。只追加不修改，随用户数据同步存储；调度算法、成功衡量指标与未来的 FSRS 参数拟合均以 ReviewLog 为**唯一事实来源**；
- F4.11 **新卡毕业与「已巩固」标准（successive relearning）**：新卡须在当次会话内达成一次**无提示的成功提取**方可进入跨会话调度；同一会话内对同一卡片至多记一次「成功」（多次答对不叠加记忆强度估计）。卡片在**连续 3 个跨会话复习中均一次通过**后标记为「已巩固」，进入流利度训练池（F15）——长期保持来自多会话分散成功，而非单会话内的重复；
- F4.12 【P1】**顽固卡（leech）处理**：同一卡片累计答错达到阈值（默认 6 次）时标记为顽固卡并暂停常规调度，触发 AI 教练介入：与用户就该卡做一轮精细加工对话（为什么是这个表达、和易混表达的差别、让用户造一个自己的例句），并可建议拆分或改写卡片后重新入队——反复失败说明卡片本身违反了适度困难区间，继续机械重复是低效的。

### F5 AI 对话教练（AI Coach）

一个「随时在线、不会不耐烦的 Pimsleur 教练」，MVP 即接入：

- F5.1 教练围绕用户正在训练的技能包发起**突发情境**（文字，语音为增强项）；
- F5.2 等待用户作答（语音或文字）；
- F5.3 **铁律：在学习者做出本轮尝试之前，AI 不得给出目标表达；学习者尝试之后，AI 必须给出目标示范**——刻意练习的定义性要件就是尝试后的即时、具体反馈，「从不示范」和「先示范」同样违反证据；该约束在系统提示词层面强制；
- F5.4 **反馈顺序：先提示自我修正、后示范**——首选引导式提示（「你想用哪个时态？」「再试一次开头」，元分析显示 prompts 效应量大于直接重铸）；学习者仍未产出正确形式时，给出明确示范并要求复述一遍；
- F5.5 反馈后无缝进入下一个情境，形成连续对话训练；
- F5.6 教练可读取用户的薄弱卡片（调度数据中低分项），优先围绕薄弱项出题；
- F5.7 对话记录保存至用户存储（见 F7），供复盘；
- F5.8 【P1】**每周实战挑战**：每周向用户发起一次「实战会话」邀请：AI 教练仅围绕该用户本周升档的卡片组织连续突发情境（约 5 分钟），完成后给出周报式反馈（本周内化清单 + 一句真实进步证据）。定位为可选加餐，不计入 streak 达标条件——教练的突发情境是天然的「可变奖励」，周节奏制造期待而不增加每日负担。

### F6 账户登录

- F6.1 支持 **Microsoft 账户**（MSAL / Microsoft Identity Platform）与 **Google 账户**（Google Identity Services）OAuth 登录；
- F6.2 登录获得的令牌同时用于请求该账户体系的云存储授权（OneDrive / Google Drive，见 F7）；
- F6.3 认证层同样抽象为 `AuthProvider` 接口，便于日后增加其他 IdP；
- F6.4 未登录时允许「本地试用模式」（数据存浏览器本地，登录后可迁移）——**这是首次使用的默认路径**（见 F9.1 先训练、后注册）。

### F7 存储抽象层（Storage Abstraction）

用户数据（进度、ReviewLog、自建技能包、对话记录）**存在用户自己控制的存储里**：

- F7.1 定义 `StorageProvider` 接口（读/写/列举/删除文档级数据 + 冲突处理约定）；
- F7.2 内置 Provider：
  - **OneDrive Provider**（Microsoft Graph API，应用专属文件夹）；
  - **Google Drive Provider**（Drive API `appDataFolder`）;
  - **本地 Provider**（IndexedDB）——离线兜底与未登录试用；
- F7.3 用户可在设置中查看和**切换**当前存储后端；切换/登录时支持数据迁移（导出→导入）；
- F7.4 训练过程先写本地、后台同步到云端（本地优先，弱网/离线不阻塞训练）；
- F7.5 数据格式带版本号，向后兼容；ReviewLog（F4.10）作为一等数据实体纳入同步。

### F8 LLM 抽象层（AI Provider Abstraction）

所有 AI 能力（对话教练、情境变体生成、答案评估）经由统一抽象层调用：

- F8.1 定义 `LLMProvider` 接口（会话式补全 + 流式输出 + 结构化输出约定）；
- F8.2 **初期 Provider：Claude CLI**——后端服务调用本机 `claude` 命令（headless `-p` 模式）完成推理；MVP 即接入；
- F8.3 预留 Provider：Claude API（Anthropic SDK）、OpenAI、国内模型（DeepSeek/通义等）；
- F8.4 Provider 可在配置中切换，业务代码不感知具体模型；
- F8.5 提示词模板集中管理（教练人设、评估规则、变体生成模板），与 Provider 解耦；F5.3/F5.4 的反馈铁律作为模板级约束固化；
- F8.6 LLM 调用经由后端代理（不在浏览器直连），密钥/本机 CLI 不暴露给前端。

### F9 新手引导（First-Run Experience）

设计原则：**首次价值时刻 = 「我在几秒内脱口而出了一句英语，而且刚才想不起来的句子，1 分钟后我答出来了」**。Onboarding 的全部使命是把用户在 3 分钟内送到这个「激活时刻」（见第 2 章）。

- F9.1 **先训练、后注册**：首次打开产品，用户必须能在不登录、不授权任何云存储的情况下直接进入第一次训练（基于 F6.4 本地试用模式）。从落地页到第一张卡展示，交互步骤 ≤ 3 步、目标耗时 ≤ 60 秒。登录与云存储授权仅在首次会话完成后引导（话术围绕「保存你刚建立的进度」）——每多一屏 onboarding，完成率下降约 10–15%，OAuth + 云盘授权是重量级摩擦，必须后置；
- F9.2 **首会话难度坡道**：新手首次会话为特制的「体验会话」（约 3–5 分钟、5–8 张卡），选卡规则：前 2 张必须是内置技能包中答对率预期最高的卡，保证用户在第一分钟内获得至少一次「流畅答对」；
- F9.3 **倒计时渐进引入**：首会话前 2 张卡不启动倒计时（或仅作视觉演示、超时不判定），第 3 张起引入标准倒计时。首次倒计时启动前用一句话说明规则（「接下来试试在 5 秒内开口——想不起来也完全没关系」）；
- F9.4 **方法论的时机化教学**：不使用启动轮播图讲解理论。方法论以「just-in-time」单句提示出现在对应交互时刻（首次答错时→「努力回想本身就在建立连结」；首次卡片重现时→「它回来了——这就是间隔回想」）。每条提示只出现一次；
- F9.5 **首会话必含重现闭环**：体验会话的编排必须保证至少一张「首次没答出的卡」在短间隔（约 30 秒 / 2 分钟）重现并被答出，且界面显式点破（「1 分钟前你还想不起来这句——现在你做到了」）。此时刻定义为产品的**激活时刻（Activation Moment）**，纳入第 8 章指标；
- F9.6 **目标设定收尾**：首会话结束画面引导用户完成一个「实施意图」式承诺：选择每日训练时段（早通勤/午休/睡前/自定义）与每日最低目标（默认「1 组 ≈ 3 分钟」）。该选择同时作为 F11.4 每日目标与 F13 提醒时间的依据。

### F10 进度与掌握度可视化

掌握度数据调度引擎里本来就有，只差诚实地呈现——可见的近目标会加速投入（目标梯度效应），「已内化卡数」是用户不愿丢弃的真实资产。

- F10.1 **卡片掌握度阶梯**：每张卡的调度状态映射为面向用户的掌握度等级（示例五级：新学 → 巩固中 → 已巩固（连续 3 次跨会话通过，F4.11）→ 稳固（达 25 天档）→ 已内化（通过 25 天档复习）），以颜色/图形统一表达；
- F10.2 **技能包掌握度地图**：技能包详情页以网格热力图展示全部卡片的掌握度分布，顶部显示汇总进度条（「已内化 12 / 40」），让「还差几张就全部内化」一眼可见；
- F10.3 **个人成长曲线**：个人主页展示近 30 天秒答率/提取延迟折线与「已内化卡总数」累计曲线——北极星指标必须让用户自己也看得到它在涨；
- F10.4 **今日训练面板**：首页核心区展示「今日到期 X 张 · 预计 Y 分钟」，而非裸卡片数（时间比张数更可承诺，配合 F4.7 积压保护）；
- F10.5 掌握度显示必须**诚实**：等级只由调度数据（ReviewLog）决定，禁止为激励目的虚增等级（见附录 A）。

### F11 连续性与每日目标

Streak 是习惯产品验证最充分的留存机制（维持 7 天 streak 的用户长期留存约 3.6 倍），但**防挫败设计不是 streak 的补丁，而是它成立的前提**（冻结机制使濒临断签用户流失降低约 21%）。

- F11.1 **每日训练标记（streak）**：用户在自然日内完成至少一个「最小训练单元」即点亮当日标记，连续天数为 streak。**最小训练单元 = 1 组 ≈ 3 分钟 / 约 5 张到期卡**，明确不要求完成整个 15 分钟会话——15 分钟是推荐量，3 分钟是保命线（忙碌日的诚实达标，而非放水）；
- F11.2 **连续冻结（Streak Freeze）**：系统每 7 个达标日自动授予 1 枚冻结（上限 2 枚）。漏训一天时自动静默消耗，用户次日回来时才被告知「昨天的连续被自动保住了」——保护行为发生在用户缺席时，回来看到的是善意而非审判。**冻结不可用任何形式购买**；
- F11.3 **断签软着陆**：streak 归零时，界面必须同时展示不可丢失的累计资产（「历史最长连续 21 天 · 已内化 34 张卡」），文案聚焦重新开始而非损失（「你的 34 张内化卡还在——它们不会因为断签消失」）。禁止哭泣角色、哀求或羞辱式文案（附录 A）；
- F11.4 **每日目标与实施意图**：用户在 F9.6 设定「每天 [时段] 训练 [1 组 / 1 会话]」——实施意图研究（元分析效应量 d≈0.65）表明「我将在 [时间][地点] 做 [行为]」的具体化承诺显著提升执行率；该时段同时驱动 F13 提醒。目标可随时下调，下调不作任何负面反馈。

### F12 会话开始与结束时刻（Peak-End）

峰终定律：用户对一段体验的记忆由峰值与结尾决定。训练过程是费力的，必须用结束画面把记忆锚定在「成长的证据」上。

- F12.1 **会话内进度条**：持续显示本会话剩余卡数/进度；进入最后 3 张卡时给轻量视觉提示（「最后 3 张」）；
- F12.2 **会话结束画面**（必须包含，按此顺序）：
  1. 完成庆祝（轻量动效 ≤ 2 秒，可在设置关闭）；
  2. **本次成长证据**：本会话秒答率、「今天新内化 N 张」、升档卡片列表；
  3. **明日预告**：「明天有 X 张到期（约 Y 分钟）——其中《___》这张卡将迎来它的 5 天检验」。预告具体的卡而非抽象数字，在本次结束时埋下下一次回访的具体期待；
  4. streak 与每日目标达成状态（衔接 F11）；
- F12.3 **峰值时刻强化**：会话中出现「上次没答出、本次流畅答对」的卡时，给予全会话最强的即时反馈（专属动效 + 文案「5 天前你还想不起来这句」）。这是由真实学习数据触发的峰值时刻，其激励优先级高于一切装饰性奖励；
- F12.4 **中途退出的体面处理**：中途退出时保存进度，已完成部分计入当日统计；退出确认文案不得愧疚施压（禁止「真的要放弃吗？」），改为陈述事实（「已完成 8 张，进度已保存」）。

### F13 回访触发（提醒）【P1，随 PWA 推送落地】

提醒是间隔重复的**功能性组成部分**（到期时间是算法算出来的，用户自己不可能知道），因此有天然正当性；节制、可控、信息有用，是提醒能长期活着（不被系统级关闭）的唯一方式。

- F13.1 **每日至多一条**：无论积压多少，每自然日至多一条训练提醒（PWA 推送；未授权推送时可选每日邮件摘要，默认关闭）。发送时间 = 用户在 F11.4 选定的训练时段；
- F13.2 **内容必须携带真实信息**：提醒正文来自调度数据（「今天 7 张到期 · 约 5 分钟 · 'Can we reschedule…' 迎来 5 天检验」），禁止空洞催促与愧疚/哀求/威胁式文案；
- F13.3 **自动降频**：连续 7 天提醒未带来任何打开行为时，自动降为每周 1 条摘要并在应用内告知；用户一键可完全关闭。禁止将「即将停发提醒」写成挽留话术；
- F13.4 **当日已达标则静默**：当日已完成最小训练单元后不再发送任何提醒；
- F13.5 【P2】**回归触发**：仅两类时刻允许额外触达：冻结被消耗的次日说明、中断 ≥ 7 天后的单次「回归模式」邀请（一次未响应即停止）。

### F14 成就与里程碑【P1】

里程碑把约 66 天的习惯养成期切成一连串近目标；但成就必须**指向掌握而非活跃**，否则会训练用户刷指标而非练技能。

- F14.1 成就仅授予两类事件：**掌握类**（首张卡达 25 天档、单技能包内化 50%/100%、累计内化 10/50/100 张、单会话秒答率 ≥ 80%）与**习惯类**（连续 7/30/66 天——66 天里程碑显式致敬习惯研究：「你已经把训练变成了习惯」）。**禁止纯活跃类成就**（「打开应用 100 次」「累计在线 10 小时」——在线时长与本产品价值主张相悖）；
- F14.2 成就达成时在会话结束画面呈现（并入 F12.2），不中断训练过程；
- F14.3 里程碑页展示「下一个最近的里程碑及差距」（「再内化 3 张 → 达成'内化 50'」），永远保持一个可见的近目标。

### F15 流利度冲刺模式（4/3/2）【P2】

- 从「已巩固」卡池（F4.11）抽取卡片组成限时轮次，同一批卡片连续三轮复现，作答时限逐轮递减（如 8 秒 → 6 秒 → 4 秒）。本模式仅使用用户已能正确输出的内容，目标是**压缩提取延迟**而非学新内容（Nation 4/3/2 技术：递减时限复述同时提升语速并意外提升准确性与复杂度）；成绩记录提取延迟变化，不影响间隔调度。

### F16 元认知校准仪表盘【P2】

- 当作答方式为语音/文字时，AI 评估结果与用户自评并行记录；周报向用户展示两者的一致率与偏向（高估/低估），并给出一句话建议（如「你有 30% 的『犹豫答出』实际含语法错误，建议评分时更严格」）——自评准确性本身可训练，展示「自评 vs 实际」差距能改善后续学习决策。

## 5. 非功能需求

| 编号 | 需求 |
|---|---|
| N1 | **Web 优先**：响应式布局，手机浏览器为一等公民；PWA（可安装、离线训练缓存） |
| N2 | **可移植性**：核心逻辑（调度、会话、模型）为纯 TypeScript 包，无 DOM/框架依赖，未来 React Native App 直接复用 |
| N3 | **隐私**：用户学习数据（ReviewLog、进度、技能包、对话）存于用户自己的云盘或本地；平台不集中存储用户学习数据 |
| N4 | **离线可用**：已下载的技能包与到期队列在离线时可正常训练，AI 教练功能可优雅降级 |
| N5 | **低延迟交互**：倒计时、翻卡、评分等训练交互必须即时响应（本地计算），不被网络阻塞 |
| N6 | **可测试性**：调度引擎与会话引擎 100% 可单元测试（纯函数 + 注入时钟） |
| N7 | **国际化预留**：UI 文案走 i18n 资源文件，首发简体中文 |
| N8 | **匿名遥测**：产品内置隐私优先的匿名事件遥测（仅事件名 + 时间戳 + 匿名安装 ID，**不含卡片内容与用户身份**），首次启动时明示并允许一键关闭；学习数据本体仍遵循 N3 不离开用户存储。没有这一条，第 8 章所有指标（含北极星）在产品侧无法统计，形同虚设 |

## 6. 技术架构建议

```
LearnSkillsAssistant/  (monorepo, pnpm workspaces)
├── packages/
│   ├── core/            # 领域模型 + 调度引擎 + 会话引擎（纯 TS，零框架依赖）
│   │                    #   ReviewLog 为一等实体；调度算法可插拔（冷启动阶梯 → ts-fsrs）
│   ├── providers/       # 抽象层接口与实现
│   │   ├── llm/         #   LLMProvider: claude-cli | claude-api | openai | ...
│   │   ├── storage/     #   StorageProvider: onedrive | gdrive | indexeddb
│   │   └── auth/        #   AuthProvider: microsoft | google
│   └── content/         # 内置技能包（JSON）+ 技能包 schema 校验
├── apps/
│   ├── web/             # React + TypeScript + Vite 前端（PWA）
│   └── server/          # 轻量 Node 后端：LLM 代理（调用 Claude CLI）、OAuth 回调
└── docs/                # 本文档等
```

- 前端：React + TypeScript + Vite，PWA（Service Worker）；
- 后端：Node.js 轻量服务，职责仅限 LLM 代理与 OAuth 辅助——用户学习数据不经过后端持久化；匿名遥测（N8）走独立轻量端点或第三方隐私友好统计；
- 语音：浏览器 Web Speech API（识别 SpeechRecognition 仅作记录参考、朗读 SpeechSynthesis 用于 TTS 跟读），零成本起步，后期可换云语音服务（同样走 Provider 抽象）。

## 8. 成功衡量

核心不是学习时长或内容量，而是**提取能力**。指标分两组，全部依赖 ReviewLog（F4.10）与匿名遥测（N8）。

### 8.1 学习效果指标（北极星组）

| 指标 | 定义 | 说明 | 优先级 |
|---|---|---|---|
| **真实保持率** | 到期复习中的**首答**正确率（不含会话内重现） | 健康区间 80–95%，默认目标 90%；**不是越高越好**——>95% 意味着调度过密、复习量陡增 | P0 |
| **提取延迟中位数**（按卡龄分层） | 题面呈现到开始作答的毫秒数 | 自动化程度的直接测量，「反应健身房」的北极星 | P0 |
| 秒答率 | 限时内流畅答对的比例 | 与真实保持率**配对解读**（调度排密即可虚高，防 Goodhart） | P0 |
| 记忆稳定性中位数 | 保持率 90% 对应的预测间隔 | 替代 v0.1 的「留存间隔」（原指标是算法参数的函数，换算法后不可比） | P1 |
| 每日复习负担 | 达到同等保持率所需的日均复习量 | 越低越好；切换 FSRS 时的验收标准 | P0 |
| 教练情境首答成功率 | AI 突发情境中无提示首答被评为可接受的比例 | 最接近真实使用场景的迁移测量 | P1 |
| 泛化率 | 迁移探针卡（F3.5）的首答正确率 | 直接衡量「举一反三」这一产品核心承诺 | P1 |
| 长期保持抽检 | 对「已巩固」≥ 30 天的卡按月抽样重测 | 区分「按时复习时答对」与「真的长期记住了」 | P1 |

### 8.2 激活与留存指标

| 指标 | 定义 | 目标参考 | 优先级 |
|---|---|---|---|
| 激活率 | 新用户中完成首次体验会话且经历 F9.5「重现闭环时刻」的比例 | ≥ 60% | P0 |
| 首价值耗时（TTFV） | 首次打开 → 第一张卡作答完成的中位耗时 | ≤ 90 秒 | P0 |
| D1 / D7 / D30 留存 | 首次会话后第 1/7/30 天有任一训练行为的比例 | 教育类基准约 D1 25–35%、D7 10–15%、D30 5–8%，逐版本抬升 | P0 |
| 7 日 4 次率 | 首周内完成 ≥ 4 个达标日的新用户比例（习惯形成的最强先导指标） | 建立基线后逐步抬升 | P0 |
| 积压健康度 | 到期未训卡中位数；触发回归模式（F4.8）的用户占比及其次周留存 | 回归模式用户次周留存应接近正常用户 | P0 |
| 会话完成率 | 开始的训练会话中完整做完的比例 | — | P0 |
| 同时段训练率 | 周内 ≥ 3 次训练发生在自选时段 ±1 小时内的用户比例（检验实施意图是否生效） | — | P1 |
| Streak 分布 | 当前 streak ≥ 7 / ≥ 30 天的活跃用户占比；冻结消耗率与断签后 7 日回归率 | — | P1 |
| 提醒健康度 | 推送授权率、提醒点开率、**提醒关闭率**（关闭率是操纵性文案的报警器） | 关闭率持续上升即回滚文案 | P1 |
| 教练对话轮次 | 每周与 AI 教练的有效问答轮数（参与度指标，非学习指标） | — | P1 |

### 8.3 指标护栏

**留存指标永远与学习效果北极星联合评估**——任何使 D7 上升但真实保持率/内化卡数下降的机制，视为伪增长予以回滚。这是附录 A 价值观在数据层的落地。

## 附录 A：动机设计红线

本产品面向学生，健康的动机设计是产品价值观。以下设计**明确禁止**：

1. **禁止愧疚/羞辱/威胁式文案与角色表演**（哭泣吉祥物、「你让 XX 失望了」、「我们要停发提醒了」式反向施压）——把学习与愧疚绑定会损害长期学习动机，且与 F2「卡住不算失败」原则直接矛盾；
2. **禁止付费修复/购买 streak 及一切「为止损付费」的设计**——将损失厌恶变现是对用户焦虑的套利；冻结必须靠训练行为获得（F11.2）；
3. **禁止虚假进度与虚假掌握度**（为留存虚增等级、注册即送「已掌握」、不衰减的虚荣进度条）——本产品唯一的护城河是「掌握度数据是真的」，等级注水则信任与价值主张同时崩塌；
4. **禁止无限内容流与「再来一组」的强制续播**——调度算法定义了「今天练完了」的诚实终点：练完就明确告诉用户「今天到此为止，明天见」。这是相对无底洞式产品的差异化优势，也符合适度困难原则（过量训练边际收益为负）；
5. **禁止倒计时/稀缺性营销话术**（「限时解锁」「今晚过期的奖励」）——卡片的到期时间是真实的记忆科学，掺入人造紧迫感会污染唯一真实的紧迫感来源；
6. **禁止以指标为目的的打扰**：每日多条推送、邮件轰炸、退出挽留弹窗、注销/关通知路径的故意加深——对 PWA 产品，一次被系统级屏蔽通知 = 永久失去触达渠道；
7. **禁止把社交压力作为核心留存杠杆**（公开排行、好友超越推送、连败公示）——焦虑型使用与「真实保持率/秒答率」北极星冲突。

**允许并鼓励的边界内做法**：诚实的进度资产、静默的善意（自动冻结）、基于真实调度数据的提醒、庆祝真实成长、结伴不对抗。

**判据一条：该设计在用户完全知情其机制后，是否仍会感谢它的存在**（自动冻结：会；哭泣吉祥物：不会）。
